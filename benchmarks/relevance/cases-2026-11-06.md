# Retrieval pilot — cases and relevance criteria (written before capture)

Six cases, two per task class. Grading scale for every case:
0 = irrelevant or wrong; 1 = related but does not answer; 2 = useful answer evidence (a competent engineer could act on it with light adaptation); 3 = directly satisfies the task.
Judge the DOCUMENT against the task, not against the query wording. Mark a document UNJUDGEABLE (not 0) when its content cannot be assessed (paywall, empty snippet).

## C1 (official-documentation navigation)
Task: the user needs the official Traefik v3 documentation statement on the order in which middlewares in a chain are applied and on what happens when a middleware in the chain errors.
Query: traefik middleware chain execution order error behaviour official documentation
3 = Traefik official docs page about the chain middleware explaining order and error behaviour
2 = another Traefik official docs page that covers middleware ordering or middleware errors
1 = third-party article about Traefik middleware
0 = unrelated

## C2 (official-documentation navigation)
Task: the user needs the official Ansible documentation page for become_user and the privilege-escalation method required for it to take effect.
Query: ansible become_user privilege escalation method documentation
3 = official Ansible privilege-escalation (become) documentation naming become_user and the method requirement
2 = another official Ansible page that covers become/become_user in less depth
1 = third-party tutorial on Ansible become
0 = unrelated

## C3 (troubleshooting)
Task: git worktree remove fails with the message that the target is a main working tree; the user needs the cause and the correct command for removing a linked worktree, including one whose HEAD is detached.
Query: git worktree remove main working tree detached head error
3 = authoritative explanation (git documentation or accepted StackOverflow answer) with the correct command
2 = related documentation on git worktree add/prune that helps but does not resolve this error
1 = tangentially related git content
0 = unrelated

## C4 (troubleshooting)
Task: a Kubernetes pod stays Pending with "0/3 nodes are available: 3 Insufficient cpu"; the user needs how to find which pods request what and how to resolve it.
Query: kubernetes pod pending insufficient cpu 0/3 nodes available diagnose requests
3 = authoritative troubleshooting content covering resource requests diagnosis and remediation
2 = related Kubernetes scheduling/requests documentation
1 = tangentially related container-resource content
0 = unrelated

## C5 (broader information seeking)
Task: the user wants the engineering trade-offs between circuit breakers and retries with exponential backoff for calls to external HTTP APIs.
Query: circuit breaker versus retry exponential backoff external API trade-offs
3 = substantive treatment of both patterns and their interaction/trade-offs
2 = substantive treatment of one pattern with partial comparison
1 = superficial mention
0 = unrelated

## C6 (broader information seeking)
Task: the user wants to know how search-engine aggregators handle duplicate results coming from multiple upstream providers, and which deduplication strategies are used in practice.
Query: search engine aggregator duplicate results deduplication across providers strategies
3 = substantive treatment of deduplication strategies across providers (URL canonicalisation, shingling, clustering)
2 = partial or single-technique treatment that still informs the design
1 = superficial mention
0 = unrelated
